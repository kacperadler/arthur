# Verify

How a worker proves its change and a reviewer checks the proof, in Arthur. Run each step in your own worktree or checkout, never in the main checkout, which holds a different tree; report each command beside its result.

1. Checks: while you iterate, the tests of each package you changed, `node --import @arthur/core/testing --test "packages/<p>/test/**/*.test.ts"` (the root's own: `node --import @arthur/core/testing --test "test/**/*.test.ts"`). Once, on the clean, committed tip: `npm run check && npm test` in one bash call with a `timeout` of 1800 seconds. Wait for it; write nothing from memory.
2. A failing test in a file the diff does not touch: run that file alone, `node --import @arthur/core/testing --test <file>`. It counts against the branch only if it fails alone too; say which.
3. Mutations: once the work is committed, `npm run mutate` in a bash call of its own (`npm run mutate -- --max <n>` runs `<n>` mutants, taken round-robin across the changed files and hunks; a run of fewer than min(25, all its mutants) does not open the review gate). A run cut by time (`not run (time)`) goes on where it stopped when `npm run mutate` is run again on the same commit with the same `--max`: rerun it until no `not run (time)` is left; the last summary counts every call. Every `survived:` line is a missing test: add it (worker) or name it as a finding (reviewer). For a condition it does not reach: invert or remove it, run that package's test files that import it, see one fail, and restore it with `git checkout -- <file>`.
4. The Goal, the way a user meets it: run the changed command as its doc page says (`npx arthur <cmd> --help` prints it), then the command itself in a temporary folder; and run each command a line you wrote tells someone to run, exactly as written.
5. Report, in the final message, each command you ran, its result (the counts from its output) and the commit it ran on.
