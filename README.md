# Arthur

Arthur runs coding agents (OMP) for one human: a small core runs each job in its own Git worktree and keeps a ticket board in plain files, and plugins add the rest (the coordinator, schedules, projects, review and merge, GitHub, YouTrack, Telegram) from one config file, `arthur.config.ts`. It exposes nothing to the internet.

**Status: in development, not usable yet.** What runs today: config loading, and `arthur config check`, which loads `arthur.config.ts` and lists the env variables the enabled plugins need, each `set` or `missing`, never their values; the plugin host, and the command registry behind the `arthur` binary (`arthur help`, `arthur <cmd> --help`) and a channel's `/name text`; `arthur run`, which starts the plugins and stops them on SIGTERM, one process per home folder; `arthur spawn`, which makes a job's worktree, record and role prompt from HEAD and runs its agent in the background, keeping the record current until the job ends; `arthur stop`, `arthur continue` and `arthur steer`, which stop a running job (SIGKILL after a grace when SIGTERM is not enough, at its time or budget limit too), resume an ended worker in place, and give a running job a correction after its next tool call; `arthur jobs`, `arthur prune` and `arthur stopall`, which list every project's jobs with their short ids, free what finished jobs hold as far as Git finds it safe, and stop every running job, answering `/jobs`, `/steer` and `/stopall` on a channel, while `arthur run` fails a job whose processes are gone on two sweeps in a row; the fake agent of the test kit; `arthur roles`, which lists the files each role's prompt reads and its model; the ticket board (`arthur ticket new|status|after`, `host.board`), which reads the project list a plugin provides, allows only the moves of its status table, moves a worker's ticket to in-progress when the worker starts, and answers `/board`, `/task` and `/findings` on a channel; the projects plugin (`@arthur/projects`), which declares the project list in `arthur.config.ts`, gives the coordinator one line per project, answers `arthur projects` and `/projects`, starts a job of `--project <name>` from that project's folder and installs each new worktree's dependencies; the orchestration plugin (`@arthur/orchestration`), which keeps the coordinator, one interactive `omp` under the env guard, running in its own tmux session while `arthur run` runs, never beside a previous one still alive, with `arthur attach` and `arthur coordinator stop`. The rest (the job's agent and limits, the plugins) is ordered in [`spec/roadmap.md`](spec/roadmap.md).
