# arthur prune

Usage: `arthur prune (<id>... | --all)`

Frees what ended jobs hold: their worktree, their branch and their record `<home>/jobs/<id>/`. `--all` frees every finished job; else the jobs named, each by its full or short id. An id that names no job, or a short id that matches two, refuses the whole prune before anything is removed. A bare `arthur prune`, with neither ids nor `--all`, prints the usage line and exits 2, so an empty id never widens the prune. Prints one line per job, `<id>: ` and what was done or kept, e.g. `<id>: worktree <path> removed; branch arthur/<id> deleted; record deleted`; `no jobs` when there is none.

Git decides what is safe, and what it refuses is kept, with the first line of what Git said:

- The worktree is removed with `git worktree remove`, without `--force`: one with changes or untracked files stays, and so do the branch and the record (`kept its worktree, branch and record: git worktree: fatal: ...`). So does one that reads a Git config key that may name a program, from the repository's shared config or the worktree's own `config.worktree`: `git worktree remove` runs `git status` in the worktree, which runs a clean filter that config names (`kept its worktree, branch and record: git worktree: <file> sets <key>, …`; the keys are listed in `docs/deploy.md`). A worktree already gone is pruned from Git's list.
- The branch is deleted with `git branch -d`: one with commits that HEAD of the repository does not have stays, and so does the record (`kept branch <branch> and the record: git branch: error: the branch '<branch>' is not fully merged`). Its worktree is removed all the same; a later prune, once it is merged, deletes the branch and the record. A read-only kind has no branch.
- A job that has not ended is kept: `kept: it is <state> (<reason>), not ended`, for example `working` or `blocked (user: <question>)`; `arthur stop` a job in a run first, and a blocked one keeps its worktree for `arthur continue`, unless `arthur stop` ends it, as it does one blocked on the user (see `arthur stop --help`).
- A plugin may keep a record: the core asks every plugin that provides `jobs.keep`, with the job (`id`, `kind`, `project`, `task`, `state`, `reason`, `branch`, `worktree`, `branch` empty for a read-only kind). Each answer that is a text is a reason to keep the record; the worktree and branch are freed all the same, and the line ends `kept the record: <reasons>`. A provider that throws ends the prune there with its error, exit code 1; the job it was asked about keeps its record.
- A job on another machine (its record's `machine`; see `arthur spawn --help`) is pruned there first, over SSH, by `arthur remote-job prune`: its worktree there, Git deciding there as above (`kept its worktree, branch and record: machine <name>: arthur remote-job prune: git worktree: fatal: ...`); its branch there, only while its tip is the one of the branch here, which its end brought here (else `kept branch <branch> there: it is not the one here`); and its record there. A job still in a run there keeps everything (`kept its worktree, branch and record: machine <name>: arthur remote-job prune: <id> is <state> there, in a run`), and so does one whose worktree there reads a Git config key that may name a program, from the repository's shared config there or the worktree's own (`… arthur remote-job prune: git worktree: <file> sets <key>, …`; see `arthur remote-job --help`). The line starts with what it did there, e.g. `worktree <path> removed there; branch arthur/<id> deleted there; branch arthur/<id> deleted; record deleted`. Then the branch here and the record here go as above. A machine that does not answer keeps everything: `kept its worktree, branch and record: machine <name>: ssh <ssh>: <ssh's last line>`; so does a machine no plugin registers now. A job that ended here `failed: machine offline` is kept until its run there ended and was copied: `kept: it ended here while machine <name> did not answer; the sweep follows its run there until its end arrives`.

The exit code is 0 whatever was kept. Refused (exit code 1, the reason after `arthur prune: `): an unknown id (`<id>: no such job in <home>/jobs`), a short id that matches two jobs (`<id> matches 2 jobs: <id>, <id>; name one by its full id`), a config or a plugin that does not load. Wrong usage prints the usage line and exits 2: a flag, no ids and no `--all`, `--all` with ids, or an empty id (`arthur prune ""`), each before anything is removed.
