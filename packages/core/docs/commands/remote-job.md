# arthur remote-job

Usage: `arthur remote-job repo|add|launch|stop|steer|continue|prune|remove|records <home> [args]`

The half of a job on another machine that runs on that machine. The main Arthur runs it there over `ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 <ssh>` (see `arthur spawn --help`); a person has no reason to. `<home>` is the machine's `home` as registered, an absolute path: Arthur's home folder there, with the job records in `<home>/jobs/`, the projects' repositories in `<home>/repos/` and the job worktrees in `<home>/repos/.arthur-worktrees/`. It needs no config there: the jobs' slice there gets the machine's own limit, its cores minus one (at least one) and `MemoryMax` `70%`, not the main Arthur's `core.jobs.cpu` and `core.jobs.memory`.

- `repo <home> <project> <commit>`: makes `<home>`, or keeps it, the user's alone there (`0700`, as `arthur doctor --help` says of the home here), then creates `<home>/repos/<project>.git`, a bare repository, when it is not one yet, and prints `present` when it holds the commit, else `missing`; the main Arthur then pushes the commit to `refs/arthur/base`, and asks again for a spawn's `fetch` (a review's branch tip, `arthur spawn --help`), which it pushes to `refs/arthur/fetch`. A push's `git receive-pack` there runs none of the hooks that repository's config names. A project name with a `/` or starting with `.` is refused.
- `add <home>`: reads the job as JSON on stdin (`job`, its `root` the repository there, its caps `cpu` and `memory` when it has them; `prompt`; `kind`, `{ resumeOnBudget, verdicts, extensions }`, the record's `resume-on-budget`, `verdicts` and `extensions`; `idleMinutes`; `since`), adds its worktree there from its `base`, on its branch or detached, and writes its record as `arthur spawn` does; a record that cannot be written removes the worktree again.
- `launch <home> <id> <agent> <slice>`: starts the job's wrapper there as `arthur spawn` does here, in the scope `arthur-job-<id>.scope` of the slice `<slice>` with the job's own caps (see "Caps per job" in `arthur spawn --help`), and returns once it wrote its `pid`. It reads the job's variables on stdin, a JSON object of the prepares' `{ NAME: "text" }` (none when empty), for the wrapper's environment. A job with caps that runs bare there (no user manager) prints `uncapped: <why>` first, which the main Arthur tells once per machine. When the wrapper did not start, the job there is ended `failed: <why>` and `<why>` is printed.
- `stop <home> <id>`: `arthur stop` of the job there; prints its line.
- `steer <home> <id>`: `arthur steer` of the job there with the text on stdin; prints the steer's number.
- `continue <home> <id> <agent> <slice> <caps> [<budget>]`: `arthur continue` of the job there, reading `{ "instruction": "<text>", "env": { "<NAME>": "<text>" } }` on stdin: the instruction, and the variables the prepares returned on the main Arthur, which go into the new run's environment only, as `launch`'s; `<caps>` (the JSON of what `jobs.limits` answered here, `{}` for none) replacing the record's caps, `<budget>` replacing its budget when given; the `beforeSpawn` checks are the main Arthur's, run before. Prints why the wrapper did not start, as `launch`.
- `prune <home> <id> <tip>`: removes the job's worktree there with `git worktree remove`, Git refusing one with changes; its branch there only while it points at `<tip>`, the commit of the branch in the main checkout (empty when it has none); then its record there. Its git calls run no hook and no `core.fsmonitor` that the repository's config there names: a program a job runs there may have set them. Prints what it removed and kept, e.g. `worktree <path> removed there; branch arthur/<id> deleted there`. A job in a run there is refused, `<id> is <state> there, in a run`; a record already gone prints nothing.
- `remove <home> <id>`: removes the job's worktree, its branch and its record there.
- `records <home> <id>=<ms>:<bytes>...`: one JSON object, by id, of each named job whose record exists there: its `state`, `reason` and `since`, read first under the record's lock, then `files`, every file of the record modified at `<ms>` (milliseconds since 1970, the machine's clock) or later, `log` among them only from its byte `<bytes>` on (`logFrom`, `0` with the whole log when it is shorter than that), `logSize`, the log's length there, and `at`, the newest modification time of any file of the record; the next copy asks from `at` and `logSize`.

Wrong usage (an unknown step, a home that is not an absolute path) prints the usage line and exits 2; a step that fails prints `arthur remote-job: <why>` and exits 1. Inside a job (`ARTHUR_JOB` set, `arthur help --help`) only `records` runs; every other step prints `arthur remote-job <step>: refused inside a job <id>: a job runs only the commands its role needs; put what the coordinator should do in your final message` and exits 1, doing nothing.
