# arthur board

Usage: `arthur board [PREFIX] [all | KIND | --kind KIND]`; on a channel `/board [PREFIX] [all | KIND]`. Without `PREFIX`, the main project (or `--project <name>` in the shell). Comes with the `orchestration` plugin, which every config holds.

The ticket board of the project whose ticket prefix is `PREFIX` (`AR`, in either case), as text, answered from `spec/build.json` and each ticket's `ticket.md` without the model: one line per ticket (id, status, Kind, title, and `after <ids>` while any ticket it waits for is not merged), the open tickets first in the order of their statuses, then the merged ones newest first, then the dropped ones; `the board is empty` when there is none. The Kind is the word of the `- Kind:` line under the ticket's Goal, `-` without one (`arthur ticket --help`).

- Without `all` or a kind: the full board when it fits one message (4096 characters, Telegram's limit), else the digest: every open ticket, the 10 newest merged, and one last line counting the rest (`+ <n> older merged, <m> dropped: the full board is /board all`), so no ticket is lost to a cut.
- `all`: the full board, whatever its length; a channel sends it in slices.
- `KIND`, or `--kind KIND`: only the tickets of that Kind, of every status, in the same order, whatever the length; `no ticket of kind <kind>` when there is none. A kind is one of the ticket template's, in either case: `feat`, `fix`, `security`, `perf`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`, `ux`. One word alone that is a project's prefix is that project's board, so for a project whose prefix is also a kind (`CI`, `UX`), `/board CI ci` names both; `--kind` always names a kind.

Refused: a prefix no project has (`unknown prefix <PREFIX>; prefixes: <each project's>`); one word alone that is neither `all`, a project's prefix nor a kind (`unknown prefix or kind <word>; prefixes: <each project's>; kinds: <the kinds>`); a word after `PREFIX`, or after `--kind`, that is neither `all` nor a kind (`unknown kind <word>; kinds: <the kinds>`; after `--kind`, `all` too); a board file broken by hand, naming the file; no project list. In the shell these exit 1; on a channel the reply is `/board failed: <reason>`. When `arthur.config.ts` does not load, the command is not there: `arthur board` prints `arthur: unknown command board`, the core's commands and why the config did not load, and exits 2.

Wrong usage (more words, a prefix with something other than letters, `--kind` with no word after it, a prefix and a kind both before `--kind`): `usage: /board [PREFIX] [all | KIND | --kind KIND]` on a channel, `usage: arthur board [PREFIX] [all | KIND | --kind KIND]` and exit code 2 in the shell.
