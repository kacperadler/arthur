# AR0319 - Check: secrets stay out of jobs, records, logs and messages

The rule of this area, split into its parts, plus the rules the code states for itself (a file's header comment or a doc line). Each row: where the code enforces it, the test that proves it (file and test name), and the verdict: `holds`, `holds without a test`, or `gap`. A gap is a `findings.md` entry, named in the row. Checked by reading, by `npm test` (below), and by two throwaway probes run in a temporary folder with made-up values, never against the VPS, the bot or a real secret: the env guard's answer to a set of calls (`envRefusal` of `packages/core/src/env-refusal.ts`), and `redact` of `packages/session/src/credential.ts` on a few shapes. Their output is quoted where a row rests on it.

Where secrets live: the `...Env` variables of the config come from the shell, else from `core.envFile` (`.env` beside the config by default, `packages/core/src/core-options.ts:33`), resolved once at the load (`packages/core/src/env.ts:40-78`) and handed to each plugin as its own `host.env` (`packages/core/src/host.ts:54`). Under the service (`docs/setup.md:138`, `EnvironmentFile=%h/.config/arthur.env`, which holds `PATH`) the process environment holds none of them. The readers of `host.env`: orchestration's MCP servers (`packages/orchestration/src/mcp.ts:79`), telegram (`packages/telegram/src/telegram.ts:37`), github (`packages/github/src/github.ts:36`), youtrack (`packages/youtrack/src/youtrack.ts:28`), models (`packages/models/src/models.ts:71`, `packages/models/src/probe.ts:100`). Nothing else reads a value (`grep -rn "host\.env" packages/*/src`).
