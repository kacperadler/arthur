# AR0321 - Check: jobs on another machine write only their own files back

The rule of this area: what comes back from another machine (copied files, branch, record) lands only in that job's record and branch; commands sent over ssh are built from checked values. Split into its parts below, plus the rules the code itself states (`packages/core/src/machine-sync.ts`, `job-machine.ts`, `remote-job.ts`, `packages/core/docs/commands/spawn.md` "On another machine"). Line numbers are of commit a2b0742. Tests are in `packages/core/test/machine.test.ts` unless named otherwise.

The trust boundary: `arthur remote-job records` answers from the machine's own record folder, which the job's agent there runs beside as the same user (`docs/deploy.md`, "A job on another machine can do there whatever that machine's user can"); so the answer is that machine's word, not this Arthur's, and every value in it is an input.

## Verdict

Rows 2, 3, 4, 7, 8 and 10 are gaps: three findings (`findings.md` F1-F3). The ssh side (rows 13-20) holds with tests. The copy's own-record rule holds for the log, the state move and the machine; it does not hold for file names or for the keys this side later acts on.
