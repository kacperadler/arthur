# AR0324 - Check: only reviewed, green code reaches main

The rule of this area: only a branch whose exact tip a review passed and whose CI passed reaches main; a review's PASS rests on what the coordinator wrote (the task `arthur review` builds), and small changes to what runs on the VPS are still reviewed.

What enforces it: the delivery plugin. `arthur merge` (`packages/delivery/src/merge-command.ts`) refuses a branch without a PASS on its tip, runs the project's checks on main after the merge and resets main when one fails; `--auto` (`auto-merge.ts`) adds the project's `autoMerge`, a PASS by a review (not a `no review`), the held paths and CI as the github plugin answers `github.ci`. The review kind (`delivery.ts`) refuses a spawn whose task has no `Ticket:`, `Branch:` and `Commit:` lines, checks out the commit detached in its `prepare`, and keeps a record per review (`review-records.ts`); the verdict is the last line of the reviewer's final message, which the wrapper writes into the record after the run. `arthur review-needed` (`review-needed.ts`) lets a small branch skip the review on the job's own record of its checks (`checks-extension.ts`).

How each row was checked: by reading the lines named, by the tests named, and by a throwaway probe (not committed) that set delivery up on the fake host in a temporary repository, as `auto-merge.test.ts` does, and ran `arthur review-needed`, a hand-written `review` spawn and `arthur merge` against it. Nothing ran against the VPS, a bot, GitHub or a client repository.

Verdicts: `holds`, `holds without a test`, `gap` (a `findings.md` entry each), or a pointer to the area whose ticket carries it.
