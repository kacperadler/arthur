# AR0326 - Check: addresses Arthur fetches stay where the config says

The rule of this area: every URL Arthur fetches (uptime sites, model providers, GitHub, YouTrack) is checked: a model provider is never a public host or a cloud metadata address; a site check cannot be pointed at loopback or metadata services unless the config says so.

Where Arthur makes a request, found by a grep of `fetch(`, `curl` and `http://`/`https://` over `packages/*/src`: the models plugin's probe (`curl --config -` through `host.jobs.run`, `packages/models/src/probe.ts:70`), the uptime plugin's site check (`packages/uptime/src/site-check.ts:12`), the GitHub REST client (`packages/github/src/github-api.ts:45`), the YouTrack REST client (`packages/youtrack/src/youtrack-api.ts:48`), the Telegram Bot API client (`packages/telegram/src/bot-api.ts:30`), and `git clone` of a project's `repo` (`packages/projects/src/clone.ts:40`). Not Arthur's own requests, listed for completeness: the agent's call to a provider from the environment the models plugin hands it (`packages/models/src/models.ts:73`), an MCP server's `url` omp opens (`packages/orchestration/src/mcp.ts:82`), `omp usage --json` (`packages/models/src/usage.ts:54`), the nvm install line printed as a fix and never run (`packages/nvm/src/nvm.ts:28,41,74`), and `ssh` to a machine (the machines plugin, its own private-address check at `packages/machines/src/machine-check.ts:33-37`).

How each row was checked: by reading the lines named, by the tests named, and by throwaway probes (not committed) run here on Node v24.21.0 and curl 8.5.0 against local HTTP servers on ports the OS picked: `isPrivate` and `checkOptions` of `model-options.ts` on a list of addresses and URL forms; Node's `fetch` with a `Bearer` header redirected across and within an origin; `checkSite` of `site-check.ts` redirected to another port; the exact config lines `probe.ts:62-69` writes, fed to `curl --config -` with and without a `.curlrc` and a proxy variable; `fetch` with `http_proxy` set, with and without `NODE_USE_ENV_PROXY=1`; `new URL` on the path forms the Telegram, YouTrack and GitHub clients append. Nothing ran against the VPS, a bot, GitHub, YouTrack, a model server or a client repository.

Verdicts: `holds`, `holds without a test`, `gap` (a `findings.md` entry each), or a pointer to the area whose ticket carries it.
