# AR0327 - Check: file modes of Arthur's home, records, sockets and locks

The rule of this area: Arthur's home, job records, logs, tmux sockets and lock files are readable and writable by Arthur's user alone, whatever the process umask; no fixed shared path in /tmp.

What the code says it enforces: one file is written with a mode, `.mcp.json` (`0o600`, "readable by its owner only", `packages/core/src/job-record.ts:23`, `packages/orchestration/src/mcp.ts:87`). Everything else under the home is made with Node's defaults, `0o777` for a folder and `0o666` for a file, less the process umask; the code never sets or reads the umask (`grep -rn umask packages/*/src`: 0 lines) and the service unit of `docs/setup.md:130-149` has no `UMask=` (`grep -rn UMask docs`: 0 lines), so the mask is the one systemd's user manager inherits, "typically 0022" (`man systemd.exec`, `UMask=`), or whatever a PAM module or the user record sets (`0002` on the machine this check ran on, `systemctl --user show arthur -p UMask`). The threat model (`docs/deploy.md:31`, `:37`) runs Arthur, the coordinator and every job as one Linux user and tells the owner to give each client its own Linux user with its own Arthur, so other users on the same host are the expected layout, not an edge case.

How each row was checked: by reading the lines and tests named, and by three local probes in a folder from `mktemp -d`, none against a VPS, a bot, a secret or a client repository: (1) with the shell's umask `0002`, Node's `mkdirSync` and `writeFileSync` as the code calls them made a folder `775` and files `664`, and `writeFileSync(..., { mode: 0o600 })` made `600`; (2) `mkdtempSync` made a folder `700`; (3) `tmux -S <folder>/sock new-session -d` made a socket `srw-------`, and the user's default folder `/tmp/tmux-<uid>` is `drwx------` (a `stat`, nothing run there). Verdicts: `holds`, `holds without a test`, `gap` (a `findings.md` entry each).
