# AR0328 - Check: dependencies, installs and the CI workflows

The rule of this area: installs and merge checks run with the least they need (scope, install scripts); the CI workflows set the token's permissions and pin actions; `package-lock.json` is what `npm ci` installs.

What enforces it: the projects plugin's install (`packages/projects/src/install.ts`): the `prepare` of every new worktree, which runs the project's `install` from `arthur.config.ts` or the frozen install of its one known lockfile, through `host.jobs.run` on the job's machine, and the same answer as `projects.install`. The delivery plugin's checks on main (`packages/delivery/src/merge-checks.ts`): after the merge commit, `projects.install` for HEAD, then `npm run check` and `npm test` when main's `package.json` declares them, as `sh -c` in the process of `arthur merge`, on the PATH `nvm.path` answers; a failure resets main and reinstalls main's own. The structure test (`test/structure.ts`) keeps `dependencies` empty and dev dependencies to the toolchain. `npm ci` itself refuses a lockfile out of step with `package.json`. The two workflows, `.github/workflows/ci.yml` and `site.yml`, are what GitHub runs; no code of Arthur reads or checks them, and both are on the always-review list and among `--auto`'s held paths.

How each row was checked: by reading the lines named and the tests named, by `npm ci` at the root and `npm ci --dry-run --ignore-scripts` in `site/` (both in step with their lockfile), by a script over both lockfiles (every non-workspace entry has `integrity` and a `https://registry.npmjs.org/` `resolved`; `hasInstallScript` on none at the root, on `fsevents` alone in the site), and by one mutation of `install.ts:11` (`npm ci` to `npm install`), which failed `install.test.ts:60`, `:79` and `:87`, then reverted. Nothing ran against the VPS, a bot, GitHub, a registry or a client repository; no file outside this folder changed.

Verdicts: `holds`, `holds without a test`, `gap` (a `findings.md` entry each), or `covered` with the ticket that already carries it.
