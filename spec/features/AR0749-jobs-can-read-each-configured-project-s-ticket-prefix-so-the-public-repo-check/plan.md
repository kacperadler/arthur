## Approach
The projects plugin writes a third home file next to `checkouts` and `folders`: `<home>/projects/prefixes`, with one `<name> <prefix>` line per configured project, in the order of `folders`. The job sandbox then shows that one file to every job. Nothing else changes: the files and paths a job could not read before stay hidden, including every other project's `project.config.ts`.

- **Writing.** `setup` in `packages/projects/src/projects.ts` already calls `keep(file, text)` for `checkouts` and `folders` on each load outside a job. A load happens at service start and on every `arthur` command. `keep` writes `<file>.<pid>` and renames it, and only when the text changed. The prefixes file uses the same `keep`, so "at start and whenever the project list changes" is covered with no new mechanism. A third file is the third example, so the three `keep` calls become one loop over `[["checkouts", "path"], ["folders", "folder"], ["prefixes", "prefix"]]`. This also keeps the package inside its line budget (see Risks).
- **Inside a job.** `setup` writes nothing there (`if (job === undefined)`), so a job never writes the file.
- **Prefix check.** The `^[A-Z]+$` rule already exists: `PREFIX` and `PIECE.prefix` in `packages/projects/src/project-options.ts:15,32`, applied by `checkProjects`. `readProjects` throws on any bad prefix before `keep` runs, so a bad prefix is never written and the last good file stays. No second filter is added; a test row proves the refusal.
- **Showing the file.** In `hidden()` (`packages/core/src/job-sandbox.ts:116`), add `join(home, "projects", "prefixes")` to the `shown` list, next to `checkouts` and `folders`. The other projects' folders read from `folders` stay hidden as now (`others` and `unkept`, lines 108 and 114).
- **Left alone:**
  - The check itself and the rewording of tracked files (AR0744).
  - `job-place.ts` and the worktree guard.
  - `stepSandbox`.
  - Other machines.
  - `CHANGELOG.md`: it says it is generated by `arthur changelog` and a hand edit is overwritten.

## Risks
- **Line budgets are full.** The structure test passes with `core` at 7682/7682 and `projects` at 600/600; I counted both with the 160-character width rule.
  - Projects: the loop replaces 4 lines with 1-2, which leaves room for the comments.
  - Core: line 116 stays at 3 counts and the comment block must be reworded within its 7 lines.
  - If the core comment cannot fit, raise `core` in `test/structure.test.ts` `BUDGETS` by the lines needed and say so in outcome.md (allowed for an existing package).
  - `job-sandbox.ts` stays at 216 lines, yellow, as now.
- **What jobs can now read.** Every job reads every project's name and prefix. Names and checkout paths were already readable (`checkouts`), so only the prefixes are new. This is the cost the owner accepted with AR-D737.
- **Bad text in the file.** A prefix is validated by `PIECE.prefix` before `readProjects` returns, so no newline or space can reach the file. Names are folder names checked by `NAME`.
- **The file is only readable as it was at a run's start** [INFERENCE from `SCRIPT` lines 49-53, which grant reads on the inode opened by `O_PATH`]:
  - If the file is missing then (first load after upgrade not yet done), the grant is skipped.
  - If `keep` renames a new file over it while the job runs, the new inode is under the hidden home and gets no grant.
  - So after a project-list change, a running job gets EACCES until its next run. `checkouts` behaves the same today.
  - AR0744's check must treat an unreadable file as "refuse", not "pass". This ticket's tests do not cover it; I flag it for AR0744.
- **Jobs on another machine.** The projects plugin writes only the local home, so the file is absent there; spawn.md already says no other project is hidden there. That is AR0744's concern.
- **Rollout.** The file appears at the first `arthur` load outside a job after the merge. The sandbox shows it from each job's next run once the service is restarted (Goal: "merged and restarted before AR0744's worker runs").
