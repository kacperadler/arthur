4. Mutate kills the processes a mutant's test run left behind

Kind: test

Evidence:

  • AR0705 findings.md, F5 (worker): after npm run mutate, a job wrapper and its fake agent were still running and had to be killed by hand.
  • AR0705 review-2.md, notes: the same leftovers, pids 1464577 and 1464697, killed by the reviewer.

Why it matters: three jobs had to find and kill leftover processes by hand, and AR0705 F5 is only deferred (client summary), with no ticket. stopGroup kills only the run's own process group. 5. The full check's output is read whole, never filtered

Kind: docs

Evidence:

  • AR0699 review-1.md, checks: "My first run of npm run check && npm test gave its counts to a grep that dropped them", so npm test was run a second time.
  • AR0699 review-2.md, checks: "its counts were lost to a grep", so the second run.
  • AR0699 review-3.md, checks: "my grep dropped its counts; these counts are from a second run".

Why it matters: three review jobs each spent an extra npm test (about 12 minutes on 3 cores) to get back counts their own filter threw away. Code cannot hold this: the checks extension takes pass or fail from the exit status, and a filter that keeps the summary is harmless, so refusing every pipe would refuse good calls. The reviewer and the worker read this step before their full run.
